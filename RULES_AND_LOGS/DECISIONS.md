# Decisions

Consequential choices made while working on the AgentKit infrastructure itself.
One line each, newest at the bottom. See `AGENTS.md` for the format and
`SESSION_LOGS.md` for the reasoning behind each entry.

Entries before 2026-08-17 were never recorded here. The 2026-07-02 session log
holds that session's decisions in prose.

- 2026-08-17: Ship `R_Rules.md` and `Mplus_Rules.md` into every project's `REFERENCES/`. Rationale: both are real coding contracts that no project was receiving.
- 2026-08-17: Have `AGENTS.md` call for those two files by task rather than adding them to the always-read list. Rationale: they total about 600 lines and most sessions need neither.
- 2026-08-17: Retitle `R_Rules.md` and mark revealjs-only sections. Rationale: roughly half of it applies to any Quarto workflow, and the old title said slides.
- 2026-08-17: Add `RENDER/` and have drivers build there, then copy into `REPORTS/` with the date appended. Rationale: Quarto empties its `--output-dir` before writing, so aiming that flag at `REPORTS/` destroys earlier reports; a scratch folder absorbs the deletion harmlessly.
- 2026-08-17: Merge seven writing style files into one master at `academic-writing-style.md`. Rationale: three lineages had drifted apart, two files each claimed to be the master, and one documented maintenance instruction would have destroyed content held nowhere else.
- 2026-08-17: Retire the rules-and-checklist lineage, and overrule its "use short to moderate-length sentences". Rationale: the measured-voice work had already absorbed every one of its rules, and that one rule contradicts his measured practice.
- 2026-08-17: Keep provenance in `SESSION_LOGS.md` rather than in the style file. Rationale: a style file should instruct, not narrate its own revision history.
- 2026-08-17: Delete both copies in `Jones_Writing_Samples/`. Rationale: one was superseded with a false parity claim, the other is regenerable from the grant skill, and neither was a master.
- 2026-08-17: Make the Codex skill a generated copy of the master. Rationale: it was an older independent lineage, and a copy with a header saying so cannot drift silently.
- 2026-08-17: Add Part 15 for outlining, fragments only, with the phrasebanks suspended. Rationale: Rich composes prose from the outline himself and does not want the agent's phrasing reaching his final document.
- 2026-08-17: Document the project update as commands in `update-existing-projects.md` rather than as `update_project.sh`. Rationale: preserves the 2 July decision to freeze at creation instead of maintaining a re-sync script.
- 2026-08-17: Move drivers and control files into `R/<Analysis>/`, one self-contained folder per analysis, with `Stata/<Analysis>/` mirroring. Rationale: a project holds several analyses and the root was accumulating one driver and one control file per analysis.
- 2026-08-17: Keep `RENDER/` and `REPORTS/` flat with no per-analysis subfolders. Rationale: Rich's call, and dated flat output stays easy to scan across analyses.
- 2026-08-17: Prefix driver output with the analysis name. Rationale: flat shared output folders make collision the default, and the driver already knows its own analysis name.
- 2026-08-17: Stop passing `--output-dir` to Quarto entirely, and render in place then move. Rationale: Quarto empties that directory, and a flat shared `RENDER/` means one analysis would destroy another's build output.
- 2026-08-17: Copy the R starters into each analysis folder rather than sharing one pair at the `R/` level. Rationale: Rich's call; self-contained analysis folders, accepting drift between them.
- 2026-08-17: Write a `.here` root marker in every scaffolded project. Rationale: drivers reach the project root through `here::here()`, which silently resolves to the working directory when no sentinel exists.
- 2026-08-17: Keep `R/RDATA/` and `R/MPLUS_OUTPUT/` flat rather than moving them inside each analysis folder. Rationale: Rich's call after the collision risk was raised; existing figure and output naming conventions keep it manageable.
- 2026-08-17: Publish the kit to GitHub as documentation of method, excluding `REFERENCES/Jones_Writing_Samples/`. Rationale: the samples are journal articles, unpublished grant text, and a live study's asset inventory.
- 2026-08-17: Publish the `reference_*.docx` files after scrubbing them to Lorem Ipsum rather than excluding them. Rationale: each contained its entire source document, and pandoc reads only the style parts, so the content can be replaced without changing what the file does.
- 2026-08-17: Make `new_project.sh` run cleanly with no reference docs present. Rationale: excluding them from the repo means every clone starts without them, and the unguarded glob failed under bash.
- 2026-08-17: Move the pandoc reference docs into a project `TEMPLATES/` folder, and the kit's copies into `_AgentKit/templates/`. Rationale: they are build assets rather than project metadata, they are restyled per project so they are working files, and the root should hold what a person reads first.
- 2026-08-17: Move the coding rule files and the session records out of `REFERENCES/` into `RULES_AND_LOGS/`, in the kit and in every project. Rationale: `REFERENCES/` had come to hold five unrelated kinds of thing, and `AGENTS.md` defines it narrowly as source material.
- 2026-08-17: Comment out the title-slide watermark block in `slides_Control.qmd` rather than shipping a placeholder image. Rationale: the scaffold does not create the image and Quarto fails rather than warns on a missing background, so the template as shipped was broken; this closes an item open since 2 July.
- 2026-08-17: Have `migrate_project.sh` delete the kit's template drivers from the analysis folder rather than leaving them beside the user's own. Rationale: two drivers in one folder is ambiguous about which one runs, and the pattern is one named path away.
- 2026-08-17: Migrate old projects by rebuilding in place, never renaming or replacing the project folder. Rationale: renaming a Dropbox-shared folder breaks the share for everyone it is shared with; the folder's identity has to survive the migration.
- 2026-08-17: Verify the backup by file count and byte total before erasing anything, and refuse if they differ. Rationale: Dropbox online-only files copy as placeholders, and a backup of placeholders would let the script destroy the only real copy.
- 2026-08-17: Name the backup `<Project>_premigration` only on success, using an `_INCOMPLETE` suffix until then. Rationale: an interrupted run should not leave something that looks like a finished backup.
- 2026-08-17: Restore by emptying and refilling the folder rather than removing and recreating it. Rationale: removing the folder breaks the share, which is what the design exists to protect; the first version had this bug and testing masked it through inode reuse.
- 2026-08-17: Have the migration move files and never edit their contents. Rationale: relocating files is safe to automate and rewriting a manuscript's YAML and driver body is not; the script prints the remaining edits instead.
- 2026-08-17: Prompt interactively for the analysis name rather than deriving it silently. Rationale: the name shapes every path afterward, and the script cannot know which control file at the root is the main one.
- 2026-08-17: Write `migrate_project.sh` in the portable shell subset despite the zsh shebang. Rationale: no zsh in the sandbox, and an untested migration script is worse than none.
- 2026-08-17: Correct the claim that VS Code Copilot auto-loads `AGENTS.md`, and document the `chat.useAgentsMdFile` setting it actually requires. Rationale: the claim was false, off by default, and was being used to justify the two-file architecture.
- 2026-08-17: Link `pdf2llm` (https://github.com/rnj0nes/pdf2llm) wherever it is referenced, and require `-o LLM_OUT` on every call. Rationale: it was named 18 times with no source, and its default output folder `llm_out/` diverges from the contract on case-sensitive filesystems.
- 2026-08-17: Regenerate the `my-writing-style` Claude skill from the master, making it the third generated copy. Rationale: the `grant-proposal-writing` skill loads it as the base standard, and it was two revisions behind, so grant drafting was running against a stale standard.
- 2026-08-17: Generate `copilot-instructions-proposals.md` from the grant skill into `templates/`, and have `new_project.sh` copy it into every project's `.github/`. Rationale: deleting the old copy left grant projects with no way to load the adjunct into Copilot, and a generated file cannot drift the way the deleted one had.
- 2026-08-17: Add `ADMIN/` to the project skeleton for agreements, regulatory correspondence, and signed forms. Rationale: administrative material had no home and was landing in `REFERENCES/`, which is source material for writing.
- 2026-08-17: Have agents read `ADMIN/` on request but never ground in it or quote it into a document unasked. Rationale: the existing rule makes text files under `REFERENCES/` quotable, and applied to agreements and correspondence that rule leaks third-party names and confidentiality terms into drafts.
- 2026-08-17: Keep `bibliography.bib` at the project root rather than moving it into `REFERENCES/`. Rationale: it is a project-level text file rather than a build asset, the root is the familiar convention, and moving it into a folder just narrowed would restart the drift.
- 2026-08-17: Require `scrub_reference_docs.py` before sharing a project whose reference docs were restyled. Rationale: rebuilding one from a real manuscript reimports that manuscript's text, citation keys, and cited DOIs into the file, where nothing displays them and nothing fails.
- 2026-08-22: Return R sources nested under `R/` to their old relative path and list them, rather than recursing the placement globs into `R/<analysis>/`. Rationale: the old stray filter claimed such files were placed when nothing had placed them, and flattening a subfolder would invent a structure and risk name collisions, while naming a file in the stray list costs the user nothing but a move.
- 2026-08-22: Scaffold rather than migrate any project that never carried the AgentKit contracts. Rationale: `migrate_project.sh` erases and rebuilds a folder to produce the same skeleton `new_project.sh` produces without deleting anything, and the `AGENTS.md` guard at the top of the script exists to catch exactly that case.
- 2026-08-22: Leave the `DATA/` question open rather than mapping project data onto `R/RDATA/` and `Stata/DTA/`. Rationale: one dataset held as `.rds`, `.dta`, and `.sav` would split across two trees with the `.sav` files stranded, so the kit needs a stated convention before any project is reshaped to fit one.
